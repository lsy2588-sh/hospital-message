## 3. 发现的安全问题与修复状态

### 3.1 中危

| # | 问题 | 位置 | 风险 | 修复建议 | 状态 |
|---|---|---|---|---|---|
| S1 | JWT 密钥存在弱默认值 `dev_secret_please_change` | `src/config/index.js` | 若部署时未配置 `.env`，攻击者可离线伪造任意角色 token | 生产环境强制校验 `JWT_SECRET`（长度 ≥ 32），缺省拒绝启动 | ✅ **已修复** |
| S2 | 登录接口无限流 | `src/routes/auth.routes.js` | 可被暴力破解弱口令（演示账号密码固定且公开） | 引入 `express-rate-limit`，登录/注册限流，仅统计失败请求 | ✅ **已修复** |

### 3.2 低危

| # | 问题 | 位置 | 风险 | 修复建议 | 状态 |
|---|---|---|---|---|---|
| S3 | Token 存储于 localStorage | 前端 `stores/auth.js` | 存在 XSS 时 token 可被窃取 | 前端保证无 XSS（Vue 默认转义已规避），或改用 HttpOnly Cookie | ⚠️ 保留（说明取舍） |
| S4 | JWT `verify` 未指定算法 | `src/utils/jwt.js` | 算法混淆攻击理论风险 | 固定 `HS256` 算法 | ✅ **已修复** |
| S5 | 无安全响应头（无 helmet） | `src/app.js` | 缺少 X-Frame-Options / X-Content-Type-Options 等 | 引入 `helmet` 中间件 | ✅ **已修复** |
| S6 | 空文件 `PATIENT_TOKEN` 已提交仓库 | 仓库根目录 | 命名暗示曾存 token，存在泄露隐患 | 删除该文件并加入 `.gitignore` | ✅ **已修复** |
| S7 | 无 CORS 中间件 | `src/app.js` | 前后端分离部署时跨域不通（当前靠 Vite proxy 规避） | 上线时按域名配置 `cors` 白名单 | ⚠️ 待上线时处理 |
| S8 | Token 有效期较长（7d） | `src/config/index.js` | token 泄露后有效期过长 | 缩短或加 refresh token 机制 | ⚠️ 保留（教学项目） |

> 说明：本系统为内存 mockDb 教学项目，无真实 SQL 注入、文件上传等攻击面，故未涉及此类检测。
